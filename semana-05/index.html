Para el Aprendizaje Práctico de este domingo

Fíjate en qué hace que un campo sea visible o no fuera de su paquete; en qué receptor necesita un setter y cuál basta para un getter; en cómo se llaman; en las dos funciones para crear errores y en qué se diferencian; y en cómo se devuelve y se revisa un error.

Una pista, no la pregunta. El cuestionario vence el domingo 29 de noviembre.

Tres ideas para llevarse

  • Encapsular es ocultar los datos y exponer métodos. En Go, un campo en minúscula solo se ve dentro de su paquete.
  • Getter lee (receptor de valor) y setter modifica y valida (receptor puntero). Así se controla el acceso desde fuera del paquete.
  • Errores: la función devuelve (valor, error) y quien la llama revisa if err != nil. No hay try ni catch.

Le pedimos una cuenta encapsulada a la IA

Escribe en Go un paquete cuenta con un struct Cuenta (titular y saldo) que no se pueda modificar desde fuera del paquete. Agrega un constructor que valide, getters, un setter para el titular y un método para retirar que devuelva un error si no alcanza el saldo. Escribe un main que maneje los errores.

Para interpretar su respuesta

  • ¿Qué impide escribir c.saldo = 1000000 desde main?
  • ¿Por qué el getter se llama Saldo() y el setter SetTitular(), con receptor puntero?
  • ¿Qué diferencia hay entre errors.New y fmt.Errorf en su código?

Lo que respondió, leído con la teoría

type Cuenta struct { titular string; saldo float64 }

func (c Cuenta) Saldo() float64 { return c.saldo }

func (c *Cuenta) SetTitular(nuevo string) error {
    if nuevo == "" { return errors.New("titular vacío") }
    c.titular = nuevo
    return nil
}

func (c *Cuenta) Retirar(monto float64) error {
    if monto > c.saldo {
        return fmt.Errorf("retiro de %.2f: %w",
            monto, ErrSaldoInsuficiente)
    }
    c.saldo -= monto; return nil
}
  • Campos en minúscula: desde main (otro paquete) no existen. Solo se llega a ellos por los métodos.
  • El setter modifica, así que necesita puntero, y valida antes de cambiar. El getter solo lee.
  • errors.New: mensaje fijo. fmt.Errorf: mensaje con datos, y %w envuelve otro error.

Código completo: ejemplos/cuentas (go run .).

Devolver un error y manejarlo

Quien puede fallar, devuelve

func NewCuenta(t string, i float64) (*Cuenta, error) {
    if t == "" {
        return nil, errors.New("titular vacío")
    }
    return &Cuenta{titular: t, saldo: i}, nil
}

Se devuelven todos los valores: nil para el puntero y el error. Si todo va bien, el error es nil.

Quien llama, revisa

c, err := NewCuenta("", 10)
if err != nil {
    fmt.Println("Error:", err)
    return
}
fmt.Println(c.Saldo())

err es una variable de tipo error: se compara con nil. if err { } no compila.

Errores propios y errores que no son errores

CódigoQué es
type ErrorDeStock string
func (e ErrorDeStock) Error() string { … }		Un error propio: cualquier tipo con el método Error() string implementa la interfaz error
var ErrNoHay = errors.New("no hay stock")Un error con nombre, para comparar con errors.Is
errorUn tipo predeclarado (una interfaz), no una palabra clave
panic(err)Detiene el programa: solo para fallas imposibles de manejar, no para validar datos
return err en una función de dos retornosNo compila: hay que devolver todos los valores, return nil, err

Si una función que lee algo falla, lo habitual es devolver el error para que decida quien llama. Imprimirlo y seguir hace que el error se pierda.

Del aula al Aprendizaje Autónomo 2

  • La rúbrica pide campos no exportados con getters y setters; los setters con receptor puntero y que validen.
  • Las funciones que pueden fallar devuelven error, y quien las llama lo maneja. Un _ en lugar de err resta.
  • Falta la interfaz: la vemos la próxima semana, la misma en que vence.
