Para el Aprendizaje Práctico de este domingo

Fíjate en cómo se declara un struct, en qué diferencia a un método de una función (el receptor), en qué cambia cuando el receptor es un puntero, en qué es un constructor en Go y en qué campos y métodos «se ven» a través de un struct incrustado.

Una pista, no la pregunta. El cuestionario vence el domingo 22 de noviembre.

Tres ideas para llevarse

  • Un struct agrupa campos: type Libro struct { titulo string; paginas int }. No hay clases: los métodos se declaran aparte.
  • Un método es una función con receptor: func (l Libro) Resumen() string. Con receptor puntero, (l *Libro), puede modificar el original.
  • Un constructor es una función normal, por convención NewLibro(...), que devuelve el struct inicializado (casi siempre *Libro).

Los objetos de Java siempre se pasan por referencia. En Go, un struct se copia, salvo que uses un puntero.

Le pedimos un modelo a la IA

Modela en Go un producto de inventario con nombre, precio y stock. Agrega un constructor, un método que calcule el valor del inventario, otro que aplique un descuento y otro que reponga unidades. Escribe un main que lo use.

Para interpretar su respuesta

  • ¿Por qué el constructor se llama NewProducto y devuelve *Producto?
  • ¿Por qué ValorInventario usa receptor de valor y AplicarDescuento receptor puntero?
  • Si teclado es un puntero, ¿por qué se escribe teclado.Nombre y no (*teclado).Nombre?

Lo que respondió, leído con la teoría

type Producto struct {
    Nombre string
    Precio float64
    Stock  int
}

func NewProducto(nombre string, precio float64) *Producto {
    return &Producto{Nombre: nombre, Precio: precio}
}

func (p Producto) ValorInventario() float64 {
    return p.Precio * float64(p.Stock)
}

func (p *Producto) AplicarDescuento(pct float64) {
    p.Precio = p.Precio * (1 - pct/100)
}
  • Un constructor es una función normal. NewX es convención, y devolver un puntero evita copias.
  • Leer: receptor de valor basta. Modificar: receptor puntero, o el cambio se pierde en una copia.
  • Con un puntero a struct, el punto desreferencia solo: teclado.Nombre.

Llamar es igual en ambos casos: mouse.Reponer(3). Si mouse es una variable, Go toma &mouse solo. Las dos formas compilan; lo que cambia es si el original se modifica.

Incrustación: composición, no herencia

type Vehiculo struct {
    placa, modelo string
}
func (v Vehiculo) Describir() string { … }

type Taxi struct {
    Vehiculo  // incrustado: sin nombre
    cooperativa string
}

func (t *Taxi) Ficha() {
    fmt.Println("Taxi", t.placa, "de", t.cooperativa)
}
  • Los campos y métodos de Vehiculo se promueven: t.placa y t.Describir() funcionan.
  • Un método de Taxi, aunque tenga receptor puntero, puede usar t.placa. Compila y funciona.
  • No es herencia: un Taxi no se puede usar donde se espera un Vehiculo. Se dice que lo «hereda» de forma coloquial.
