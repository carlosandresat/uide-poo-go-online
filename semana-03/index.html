Para el Aprendizaje Práctico de este domingo

Distingue lo que tiene tamaño fijo de lo que crece; qué cuentan len y cap; qué funciones integradas (no métodos) agregan, copian y borran; qué pasa con el arreglo cuando cambias un slice; y cómo se pregunta si una clave existe.

Una pista, no la pregunta. El cuestionario vence el domingo 15 de noviembre, el mismo día que el Aprendizaje Autónomo 1.

Tres ideas para llevarse

  • Array: tamaño fijo y parte del tipo. [3]int y [4]int son tipos distintos. Se comparan con ==.
  • Slice: una ventana sobre un arreglo, con longitud (len) y capacidad (cap). Crece con s = append(s, x).
  • Map: pares clave-valor. m[k] = v guarda, v, ok := m[k] pregunta si existe y delete(m, k) borra.

En Go no hay métodos como .add(), .pop() o .remove(): se usan funciones integradas (append, copy, delete, len) y el rebanado s[i:j].

¿Qué imprime este programa?

notas := make([]int, 2, 5)
notas = append(notas, 7)

Sigue el slice, paso a paso

LíneaQué pasalen · cap · contenido
make([]int, 2, 5)Crea 2 elementos con el valor cero y reserva espacio para 52 · 5 · [0 0]
append(notas, 7)Agrega después de los existentes; cabe en la capacidad3 · 5 · [0 0 7]
PrintlnImprime longitud, capacidad y contenido3 5 [0 0 7]

Respuesta: 3 5 [0 0 7]. El segundo argumento de make es la longitud: esos elementos ya existen. El tercero es la capacidad: espacio reservado, todavía no visible.

La IA escribe un registro de calificaciones y lo leemos con la teoría. Después, vemos qué pasa en memoria con un slice.

Le pedimos un registro a la IA

Escribe en Go un registro de calificaciones: un map de estudiante a lista de notas, una forma de agregar notas, el promedio de un estudiante (avisando si no existe), eliminar a un estudiante y mostrar todos.

Para interpretar su respuesta

  • ¿Por qué append(notas[nombre], nota) funciona aunque el estudiante no exista todavía?
  • ¿Para qué sirve el ok de lista, ok := notas[nombre]?
  • ¿Por qué el listado sale en otro orden cada vez que lo ejecutamos?

Lo que respondió, leído con la teoría

notas := make(map[string][]float64)

notas[nombre] = append(notas[nombre], nota)

lista, ok := notas[nombre]
if !ok || len(lista) == 0 {
    return 0, false
}

delete(notas, "Luis")

for nombre, lista := range notas {
    fmt.Println(nombre, lista)
}
  • Una clave que no existe devuelve el valor cero: aquí, un slice nil. Y append sobre nil crea el slice.
  • ok distingue «no existe» de «existe y vale cero». Sin él, un 0 sería ambiguo.
  • El orden de range sobre un map no está garantizado. Si importa el orden, usa un slice.

Código completo: ejemplos/calificaciones/main.go.

El arreglo detrás de un slice

Un slice guarda tres cosas: dónde empieza, cuántos ve (len) y cuántos caben (cap). Mientras comparte el arreglo, cambiar uno cambia el otro. Pruébalo con ejemplos/slices.

Maps: lo que hay que saber

delete(stock, "tinta")Borra la clave; si no existe, no hace nada

var m map[string]int y luego m["x"] = 1Panic: un map nil se puede leer, pero no escribir

La clave puede ser de cualquier tipo comparable con ==, también uno tuyo: un struct de campos comparables sirve. Un slice, un map o una función no pueden ser clave.

¿Slice o map? Piensa en tu Aprendizaje Autónomo 2

Slice, cuando…

  • importa el orden (historial, cola de pedidos);
  • recorres todo casi siempre;
  • los elementos no tienen una clave natural.

Map, cuando…

  • buscas por una clave (código, correo, ISBN);
  • necesitas saber rápido si algo existe;
  • quieres evitar claves duplicadas.

En el Aprendizaje Autónomo 2 la rúbrica pide justificar esta elección. Empieza a anotarla en tu README.md.

Regla de fondo: un array se copia entero al asignarlo o pasarlo a una función; un slice solo copia su descriptor (puntero, len, cap). Es barato, pero comparte. Todo esto se ejecuta en ejemplos/memoria.
